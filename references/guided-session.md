# 陪用户走完标准流程

标准顺序始终为：生成人脸 → 用户明确 approve → 上传服装或明确无输入 → 最终 Character reference sheet。这里只调整解释节奏，不另设一个以生活场景/视频为结尾的主流程。完整阶段和输入合同见 workflow.md。

## 第一步：脸

先利用已知人物方向、用途与风格，只问影响结果的一两个关键偏好。给一份简短具体的骨相与妆容方案，用户明确要求实际出图时生成清楚的基准脸。不要一开始同时生成全身、换场景或增加多套衣服。现成人脸被用户指定为身份图时可直接进入认可环节。

## 第二步：用户认可

展示实际图，具体检查头姿、目光、妆容和纹理，让用户认可具体脸部版本。用户改一项就只改该项，通常一到两次定点修正后说明结果；新候选未认可时不提前做设定表。不能把用户只认可“风格”当作已选中某张脸。

## 第三步：服装

脸被认可后，普通对话请用户上传服装参考，或回复“无输入/无/你搭配”。此选择是必要输入，不是自动假设；没有附件不能代替“无”。不要使用只支持文字的提问表单让用户上传文件。

有服装图就锁定其款式、配色、材质、层次和已提及设备，参考照片里的人脸不带入。无输入就按当前用途及可见衣着做简洁统一搭配，补全下装和鞋，并记录哪些是新设计；无需再添加一轮泛泛的搭配批准。

用户在同一条消息已认可脸并给出服装或选择无输入时一次推进，不重复问已答事项。后续只在具体缺失会影响服装还原时问必要细节。

## 第四步：最终设定表

按 character-sheet.md 制作白底写实三视图、六种可区分表情、服装/设备必要细节与配色板。优先保证同一人、同一衣服、真实侧背、表情特写够大、无文字水印。需要修改时编辑当前设定表，仍引用最初身份图，不重新造脸。

交付最终设定表、身份图、完整实际 prompt 与服装来源记录后，本工作流结束。场景图、自拍和视频都等待用户额外委托，不作为下一步默认提示。

## 每回合怎样说

说明已经完成什么、正在等哪一个具体输入。解释当前选项即可，不倾倒 JSON 或完整参数清单。人脸认可和服装选择是用户明确要求保留的两个环节；其它可逆细节给出具体建议，不每一步重复索取“是否继续”的确认。
