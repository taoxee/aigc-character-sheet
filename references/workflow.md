# 标准工作流：人脸 → 用户认可 → 服装 → 最终设定表

最终产物固定为 Character reference sheet。这四步适用于用户委托完整人物制作时；仅改文字 prompt、分析或编辑已有素材的请求按本轮范围执行，不自动开启完整生图。

## 阶段与推进条件

| 阶段 | 执行 | 进入下一阶段的条件 |
|---|---|---|
| face-draft | 设计人物，生成基准脸或使用用户指定人脸 | 有实际可查看的人脸图 |
| awaiting-face-approval | 展示当前候选，等待反馈；按指定项修正 | 用户明确认可当前脸或明确选定某张既有图 |
| awaiting-clothing | 接收服装图，或“无输入/无/你搭配”的明确选择 | 服装来源已确定，不能用没附件代替选择 |
| ready-for-sheet | 锁定脸与服装要求，制作设定表 | 图已生成并实际检查 |
| sheet-delivered | 交付最终设定表、身份图和实际 prompt/服装来源 | 默认完成，不自动转场景或视频 |

人脸认可要指向具体版本。用户只是在改风格、讨论 prompt、说“继续改”，不能当作认可；如“这张可以，就用她”或在指向当前图时认可并要求下一步，则可登记。若用户已经在同一句里认可人脸并提供服装或说无输入，不拆成重复问题。

服装步骤用普通对话告知：“请上传服装参考图；没有的话回复‘无输入’，我会按人物用途搭配。”不要用只能接收文字的表单工具要求上传图片。用户之前已提供有效服装参考或明确要求自行搭配时，保留其输入，不再追问。

用户未认可新候选脸前，不提前生成全身设定表。没收到服装选择时保留阶段，不擅自套模板服装。已说无输入则按当前人物用途与可见服装补全一致搭配，直接推进，无需再加一轮搭配批准。

## 内部状态

在复杂任务的 PLAN.json 中可加入 workflow，交给 `scripts/check_design.py`。示例：

```json
{
  "stage": "ready-for-sheet",
  "final_product": "character-reference-sheet",
  "face_image": "character-base-v1.png",
  "face_approved": true,
  "face_approval_evidence": "用户明确选定当前人物版本的消息摘要",
  "clothing": {
    "mode": "none",
    "reference_images": [],
    "choice_evidence": "用户明确回复无输入"
  },
  "sheet_image": null
}
```

这是 workflow 子对象，不是完整 PLAN.json。mode 取 pending/provided/none；provided 必须列出真实服装图；none 不列服装图但保留用户明确选择。ready-for-sheet 与 sheet-delivered 必须有已认可脸与已确定服装；sheet-delivered 必须有最终图片路径。

记录的布尔值和消息摘要只是执行者的可追溯记录，程序无法证明用户真的认可或服装符合图像，仍要核对实际对话和图片。未生成图不能把状态改成 delivered。

## 最终交付

主文件是用户最终选中的设定表。另保存原始 identity_anchor、服装参考角色、是否无输入、实际完整 prompt、目标与实际尺寸、已知偏差。设定表不是新身份锚点的替代：后续额外要求换场景时，仍优先用原始人脸锁脸，用设定表补服装/侧背信息。

本次固化的历史案例在人脸后直接由助手补全服装，再获用户认可；当时没有单独记录“上传/无输入”的选择。保留它作为成图和模板，不伪造此前已执行过新流程。后续新任务按此四步运行。
